# External entity and canonical distribution policy

Only the owner may change third-party profiles, publish a syndication, create a public research repository, or conduct outreach. This document provides the safe repository-side checklist.

## Verified-profile inventory

Maintain owner-held verification for each candidate profile before adding it to `_data/authors.yml` as `sameAs`: ownership/access, preferred name, current headshot, short bio, canonical `https://nikgo.com/about/` URL, topic terms, last review, and any factual claims. Do not list a directory entry, old account, or unverified product profile as an owned identity.

## Distribution rules

- Link original work to its canonical nikgo.com page.
- Syndicate only where the destination supports a canonical/original-source link; otherwise publish a materially adapted excerpt with a conspicuous original link.
- Select topical, reader-useful destinations. Do not buy links, exchange sitewide links, automate generic outreach, or create false personas/testimonials.
- For released research materials, ensure the research landing page and repository link to each other and give a version, date, license, and citation instructions. If no approved public artifact exists, state that availability boundary plainly instead of creating an empty repository.

## Safe log format

Use a private log, never a committed contact database: date, owner, destination, canonical target, publication/syndication type, canonical/original-link behavior, outcome, and next review. Do not store personal contact data or account credentials in this repository.
